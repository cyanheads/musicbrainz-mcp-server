# 0.1.9 — 2026-10-08

## Changed

- **Error results** (`@cyanheads/mcp-ts-core` 0.13.14) no longer carry server stack traces (0.13.7), request context fields (0.13.8), or `data.rootCause` (0.13.13). They carry `data.requestId`, and the `content[]` text ends with `request <id>` (0.13.10).
- **Recovery hints** are filled by the framework for each declared `errors[]` entry (0.13.10), so the tools and the `musicbrainz://{entity_type}/{mbid}` resource drop their `ctx.recoveryFor` forwards. Callers receive the same hints.
- **Mis-typed arguments** are repaired before validation: an integer sent for a string field and a JSON-stringified object (0.13.9); a numeric or boolean string for a number or boolean, a lone string for an array, and `null` at an optional key (0.13.14).
- **Argument rejections** name the field paths behind them (0.13.9), and the `-32602` result is bounded in size (0.13.14).
- **Upstream fetch errors** name the URL by origin only, e.g. `https://musicbrainz.org/…` (0.13.12).
- **`server.json`** npm entries launch through `npx` (`runtimeHint`) without `run start:stdio` / `run start:http` arguments; the HTTP entry sets `MCP_TRANSPORT_TYPE=http`.
- **Dockerfile** installs production dependencies in a `deps` stage on `$BUILDPLATFORM`, cross-installing with `--os`/`--cpu` and removing musl bindings, so no stage runs JavaScript under QEMU. Base images move to Bun 1.4.2; `MCP_FORCE_CONSOLE_LOGGING` is no longer set.
- **`.env.example`** documents `LOG_TOOL_FAILURE_PAYLOADS` and `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES` (failed-call payload logging) and `OTEL_EXPORTER_OTLP_LOGS_ENDPOINT` (OTLP log export), both opt-in (0.13.8), plus the log rate-limit and per-signal OTLP endpoint variables.
- **CodeQL workflow** runs `actions` and `javascript-typescript` as separate matrix jobs under the `/language:<language>` category.
- **Maintenance scripts, `framework-skills/`, `CLAUDE.md`, `AGENTS.md`, and README** synced to the 0.13.14 templates; `.gitignore`, `.dockerignore`, and `.mcpbignore` exclude `.env*` variants (`.mcpbignore` also `tests/`, `logs/`, `.cache/`).

## Fixed

- **Recovery hints** on `musicbrainz_get_release_group`, `_get_release`, `_get_recording`, `_get_work`, and `_get_label` named `musicbrainz_search_entities (entity_type=…)`; the parameter is `entityType`, and the hints now say so.
