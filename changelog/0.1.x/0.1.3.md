# 0.1.3 — 2026-06-19

## Added

- **`get_release_group` editions cap signal** — the embedded `releases` list is genuinely capped at one page (25) by the WS/2 lookup endpoint, so a full page now emits `truncated`/`shown`/`cap`/`notice` enrichment pointing at `musicbrainz_browse_entities` (`target_type=release`, `link.release-group=<mbid>`) for the complete set ([#2](https://github.com/cyanheads/musicbrainz-mcp-server/issues/2)).

## Changed

- **`lookup_identifier` ISRC** — `resolveIsrc` requests `inc=artist-credits`, so recordings carry the real credit instead of the `"Unknown artist"` fallback ([#3](https://github.com/cyanheads/musicbrainz-mcp-server/issues/3)).
- **`lookup_identifier` ISWC example** — replaced the non-resolving `T-345246800-1` with `T-010.140.236-1` and corrected the format note to the canonical dotted notation `T-DDD.DDD.DDD-C` in the recovery hint and input description ([#4](https://github.com/cyanheads/musicbrainz-mcp-server/issues/4)).

## Removed

- **`get_work` false truncation** — the work lookup returns recording relationships unbounded, so the `truncated`/`shown`/`cap`/`notice` enrichment and its one-page-cap guard are gone; descriptions now state the relationships are returned in full ([#1](https://github.com/cyanheads/musicbrainz-mcp-server/issues/1)).
