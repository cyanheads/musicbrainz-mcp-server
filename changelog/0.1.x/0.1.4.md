# 0.1.4 — 2026-06-19

## Changed

- **`createApp()` identity** — dropped the `websiteUrl` field; the in-code identity canon is `name` + `title` only. The server manifest at `/.well-known/mcp.json` and the SDK `initialize` response no longer emit `websiteUrl`.
- **`@cyanheads/mcp-ts-core` `^0.10.6` → `^0.10.8`** — adopts the upstream `0.10.7`/`0.10.8` line: Canvas SQL gate now classifies a `SELECT`-shaped statement that fails to prepare (mistyped column, unknown function) as `ValidationError` with `data.reason: 'invalid_sql'` and the DuckDB binder detail in `data.binderMessage`, reserving `non_select_statement` for genuine non-`SELECT`s ([#236](https://github.com/cyanheads/mcp-ts-core/issues/236)); `DuckdbProvider.describe({ tableName })` qualifies its pushed `WHERE` filters with the `t` alias, fixing the ambiguous-column Binder Error on every filtered describe ([#235](https://github.com/cyanheads/mcp-ts-core/issues/235)); `devcheck` and the changelog/antipattern/skill-version scripts gain fresh-scaffold and worktree-deletion guards ([#237](https://github.com/cyanheads/mcp-ts-core/issues/237), [#242](https://github.com/cyanheads/mcp-ts-core/issues/242), [#243](https://github.com/cyanheads/mcp-ts-core/issues/243)); biome `2.4.16` → `2.5.0`; the new `ctx.content` collector for image/audio blocks ([#239](https://github.com/cyanheads/mcp-ts-core/issues/239)).
- **Synced framework skills and `scripts/`** — re-mirrored the framework `skills/` (including seven `metadata.version` bumps the version-gated sync had skipped) and the `devcheck`/changelog/antipattern/skill-version scripts to the upstream `0.10.8` versions; reconciled the `devcheck.config.json` `outdated` allowlist to empty now that both tracked deps are current.

### Dependencies

- `@cyanheads/mcp-ts-core` `^0.10.6` → `^0.10.8`
- `@types/node` `25.9.3` → `26.0.0`
