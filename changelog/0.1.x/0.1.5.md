# 0.1.5 — 2026-06-20

## Changed

- **`@cyanheads/mcp-ts-core` `^0.10.8` → `^0.10.9`** — adopts the upstream tooling additions: `lint:packaging` now validates the plugin marketplace manifests (`.claude-plugin/plugin.json`, `.codex-plugin/plugin.json`, `.codex-plugin/mcp.json`) for non-empty descriptions and identity/install correctness — display fields carry the unscoped machine name while the `npx -y` install arg carries the full package name — gated by the new `devcheck.config.json` `packaging.pluginManifests` flag ([#240](https://github.com/cyanheads/mcp-ts-core/issues/240)); a new `Dependency Specifiers` devcheck step rejects floating specifiers (`latest`, `*`, pre-release dist-tags) in `package.json` dependency sections and the `bun.lock` workspaces map, catching the `bun update --latest` case where the lock's workspace map is written with a literal `latest` dist-tag that re-resolves past the `package.json` range ([#246](https://github.com/cyanheads/mcp-ts-core/issues/246)).
- **Synced framework `scripts/` and skills** — re-mirrored `scripts/devcheck.ts` (plugin-manifest packaging gate + `Dependency Specifiers` step), `scripts/lint-packaging.ts` (plugin-manifest validation), the new `scripts/check-dependency-specifiers.ts`, and the `polish-docs-meta` skill (`2.8` → `2.9`) to the upstream `0.10.9` versions; added `packaging.pluginManifests: true` to `devcheck.config.json`.

### Dependencies

- `@cyanheads/mcp-ts-core` `^0.10.8` → `^0.10.9`
