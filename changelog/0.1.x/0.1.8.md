# 0.1.8 — 2026-09-22

## Fixed

- **`musicbrainz_get_cover_art`** verifies an unknown MBID against MusicBrainz on a Cover Art Archive 404 ([#6](https://github.com/cyanheads/musicbrainz-mcp-server/issues/6)) — the archive answers the same 404 for a real entity with no art and for one it has no record of; the tool now returns `invalid_mbid`, `entity_not_found`, or the genuine no-art success. An unreachable check keeps the no-art success with existence flagged unconfirmed.
- **`musicbrainz_search_entities`** rejects a whitespace-only `query` locally as `blank_query` ([#7](https://github.com/cyanheads/musicbrainz-mcp-server/issues/7)) instead of forwarding it upstream for a generic 400.
- **`musicbrainz_get_release_group`**'s `coverArt` now comes from the Cover Art Archive ([#8](https://github.com/cyanheads/musicbrainz-mcp-server/issues/8)) — WS/2 carries no `cover-art-archive` stub at the release-group level. The lookup runs concurrently with the WS/2 lookup, bounded; a failed lookup omits `coverArt` with a notice instead of reporting `exists: false`.
- **`musicbrainz_lookup_identifier`** accepts only digits for a barcode ([#9](https://github.com/cyanheads/musicbrainz-mcp-server/issues/9)) — spaces and hyphens are stripped first, anything else (including a Lucene wildcard) is rejected as `invalid_identifier` before the search call.
- Typed error contracts on the six MBID `get_*` tools now branch on literal reasons ([#14](https://github.com/cyanheads/musicbrainz-mcp-server/issues/14)) so the error-contract lint rules can verify them; behavior is unchanged.
